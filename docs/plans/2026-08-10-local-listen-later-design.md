# 本地稍后听产品设计

- 日期：2026-08-10
- 状态：已经用户确认
- 适用产品：“声音导演”离线 macOS 桌面应用
- 产品阶段：从单次文字转语音工具升级为可重复使用的本地听读工作流

## 1. 决策

下一阶段不继续扩展夸张情绪，也不复制完整的 NotebookLM。产品主路线确定为：

> 一款离线优先的“稍后听”桌面工具：把没时间看的资料，自动变成自然、可修改、可继续收听的普通话音频。

产品主体采用“本地稍后听”路线，同时保留现有个人音色与局部重做能力。知识库问答、多主持人播客和复杂模型控制不进入本阶段。

## 2. 选择理由

当前应用已经能完成普通话朗读、个人音色、连续语义段、断点恢复、局部重做和通用音频导出，但主要依赖手动粘贴文字。它解决了“能不能生成”的问题，还没有形成用户反复回来的理由。

刚需化的关键不在增加更多音色参数，而在完成整个任务：

1. 用户遇到一份来不及看的内容。
2. 把内容放进应用，不手工整理格式。
3. 应用生成适合连续收听的普通话音频。
4. 用户在通勤、走路或做家务时继续听。
5. 某句话不自然时，只修改和重做那一段。

因此本阶段同时解决两个已经确认的问题：

- 提高重复使用频率，从“一次生成”变成持续积累的听读箱。
- 以自然、稳定和可修正为优先级，不追求强烈但做作的情绪表演。

## 3. 目标用户与核心任务

首批目标用户是使用 Apple Silicon Mac、主要阅读普通话内容的人，尤其包括：

- 保存了大量文章、PDF，却没有时间坐下来阅读的人。
- 希望把课程、采访、会议录音或本地视频转换成可听内容的人。
- 需要用个人音色制作口播，但不想把素材上传到云端的创作者。
- 对隐私、订阅额度或内容外传敏感的用户。

核心任务定义为：

> 当我没有时间看完一份资料时，我想把它交给电脑，让电脑在本地整理成自然音频，以便稍后继续听；如果局部不满意，我只修那一小段。

## 4. 用户体验原则

### 4.1 首页只让用户做一件事

首页主动作是“放进一个想听的内容”，支持：

- 粘贴文字。
- 粘贴网页链接。
- 拖入 PDF。
- 拖入本地音频或视频。

首页同时展示最近听读和播放进度，不展示模型名称、量化精度、内存策略、分段规则或 Worker 状态。

### 4.2 默认流程保持三步

1. 放入内容。
2. 选择声音。
3. 开始生成并收听。

导入、清理、分段、发音检查、质量检查和失败重试都由应用自动处理。只有发生问题或用户主动展开时，才显示高级编辑。

### 4.3 不等待全文完成

应用以语义段为单位生成。第一段完成后即可播放，后续段落继续在后台排队。用户不需要等整篇资料生成完才开始听。

### 4.4 复杂能力藏在需要它的地方

高级区域可以提供：

- 对照来源文字。
- 修改单个语义段。
- 单段重新生成。
- 发音词典。
- 自然程度和情绪强度微调。
- 导出格式和保存位置。

强情绪不再作为首页选项。默认表达为“自然克制”，微调只影响当前段或当前项目。

## 5. 内容导入范围

### 5.1 第一阶段支持

1. **纯文字**：复用当前输入和朗读稿流程。
2. **网页**：提取标题与正文，去除导航、广告、评论和重复页脚；保留原始链接。
3. **PDF**：优先使用系统 PDFKit 提取可选择文字；扫描版 PDF 暂不自动 OCR。
4. **本地音频和视频**：使用系统媒体能力读取音轨，再通过本地语音识别生成文字。

### 5.2 音视频处理顺序

1. 文件已有可读取字幕时优先使用字幕。
2. 没有字幕时提取音轨并在本地转写。
3. 保留转写结果和时间信息，后续可定位来源。
4. 转写失败不删除原文件，也不自动上传云端。

本地转写优先评估可直接嵌入 Swift 应用的开源实现，例如 WhisperKit。正式纳入前必须验证许可证、最低系统版本、模型体积、M1 8GB 峰值内存和普通话准确率。

### 5.3 后续支持

- 视频网站公开字幕链接。
- 扫描 PDF 的本地 OCR。
- Markdown、Word 和电子书。
- 从浏览器或系统分享菜单发送到听读箱。

首版不内置绕过 DRM、登录限制或访问控制的视频下载能力。平台链接导入必须遵守来源平台规则，并以用户有权处理的内容为前提。

## 6. 听读项目模型

继续使用现有 `NarrationProject` 作为项目核心，不另建一套互不兼容的数据系统。下一格式版本增加来源和播放状态：

- 来源类型：文字、网页、PDF、音频、视频。
- 来源标题和原始定位信息。
- 本地原文件的受管副本或安全书签。
- 导入状态、进度和可理解的失败原因。
- 原始提取文字和当前朗读稿。
- 已播放位置、最后播放时间和是否完成。
- 转写时间段与朗读语义段之间的可选关联。

旧项目迁移后默认为“文字来源”，原有音频、分段和导出记录保持不变。

本地数据继续保存在应用自己的用户数据目录。删除项目时延续现有“移到废纸篓”策略，避免不可恢复删除。

## 7. 导入与生成状态

每个项目采用可恢复状态机：

1. `captured`：已经记录来源。
2. `extracting`：正在提取正文、字幕或音轨。
3. `transcribing`：正在本地转写。
4. `ready`：文字已经可以检查和生成。
5. `generating`：正在按语义段生成音频。
6. `playable`：至少一个语义段已经可播放。
7. `completed`：全部语义段生成完成。
8. `needsAttention`：需要用户处理密码、空内容、损坏文件或不支持格式。

导入和生成都按阶段原子保存。应用退出、崩溃或用户取消后，重新打开只继续未完成阶段，不重复处理已经成功的内容。

## 8. 自然度与质量策略

下一阶段不依靠更强烈的“开心、愤怒、悲伤”标签提升真人感，而是优先处理长期听感：

- 按自然段、语义和上下文组成连续语义段。
- 数字、日期、英文缩写和专有名词先做朗读规范化。
- 同一项目复用音色与上下文，减少反复起调。
- 建立项目级和全局发音词典。
- 检测削波、直流偏移、异常底噪、过长静音和突变。
- 明显异常的语义段自动重试一次，不把坏结果直接拼进成品。
- 相邻语义段统一响度并使用短交叉淡化，降低拼接断层。
- 修改一句时只让所属语义段失效，其他音频继续复用。

质量检测默认在后台运行。只有自动修复仍失败时，才向用户显示“这一段需要重做”，不显示复杂声学指标。

## 9. 设备与离线策略

- 不升级 macOS，不修改系统设置，不安装 Homebrew、Docker 或系统级运行时。
- 继续以 macOS 14 兼容路线为硬边界；只支持 macOS 15 的能力不能成为唯一实现。
- M1 8GB 是最低兼容目标，必须在真实设备上验证，不能用 32GB 开发机限额测试代替正式结论。
- 16GB 和 32GB 设备自动采用更快的并行、缓存或高质量档位，普通用户不手动选模型。
- 应用默认全程离线。未来若增加云端增强，必须由用户主动开启并明确显示哪些内容会离开设备。

为了控制首次安装体积，后续可把语音识别模型设计为可选的本地模型包；没有安装转写包时，文字、网页和可提取文字的 PDF 仍可正常工作。

## 10. 项目列表与继续收听

左侧“我的朗读”升级为“我的听读”，每个项目显示：

- 标题和来源类型。
- 已完成生成比例。
- 已听进度。
- “继续听”“继续生成”或“需要处理”的单一状态。

项目按最近播放时间排序。播放器保留播放、暂停、停止和 0.1×～3.0× 调速，并记录上次位置。打开应用时不自动播放，但可以一键继续。

## 11. 导出与笔记

当前 WAV、M4A 和 MP3 导出继续保留，导出的文件在没有安装应用和模型的设备上也可播放。

后续增加最小化笔记出口：

- 导出原文或转写稿为 Markdown／纯文本。
- 复制来源链接和当前选中段落。
- 使用 macOS 分享面板发送到用户已有的笔记软件。

首版不为每一种笔记软件分别制作账号登录和同步界面，避免把用户带入复杂配置。

## 12. 开源复用边界

本阶段坚持“选择性复用，不整套搬入”：

- 继续借鉴 Open Notebook 的来源、后台任务和音频产物工作流，但不引入其完整 Web 前端、数据库、向量检索和多模型配置。
- 网页正文提取优先评估成熟、许可证清晰的正文抽取方案。
- 本地语音转写优先评估 WhisperKit 等 Apple Silicon 原生实现。
- 复用代码必须记录来源、固定提交、许可证和本地修改；不确定的自定义许可证只做研究，不进入发布包。

## 13. 明确不做

本阶段不做：

- 更多首页情绪按钮。
- 多模型匿名赛马或让普通用户手选模型。
- 完整知识库、向量搜索和资料问答。
- 多主持人播客。
- 多账户、团队空间和云同步。
- 绕过平台限制的视频抓取。
- 为追求新模型而要求用户升级 macOS。

## 14. 验证标准

### 14.1 可用性

- 支持的来源最多三步开始生成。
- 文字、网页、可提取文字的 PDF 和本地音视频都有清楚的导入结果。
- 第一语义段完成即可播放，不等待全文。
- 应用重启后能恢复导入、转写、生成和播放位置。
- 旧项目迁移后不丢文字、音频、音色、分段或导出记录。

### 14.2 听感

- 默认表达自然克制，不出现明显表演腔。
- 连续收听十分钟时，段落起调和响度没有明显跳变。
- 自动质量检查能拦截明显爆音、电流感、异常静音和损坏音频。
- 用户发现问题时，可以只修改和重做相应语义段。

### 14.3 设备和隐私

- 断网后完成受支持来源的导入、转写、生成、播放和导出。
- 在真实 M1 8GB 与 16GB 设备上记录首段时间、全文时间、峰值内存和长时间稳定性。
- 检查应用只写入自己的用户数据、缓存和用户选择的导出目录。
- 构建和运行过程不调用系统升级、系统配置修改或外部系统包管理器。

### 14.4 产品假设验证

在小范围试用中重点观察：

- 用户是否在一周内导入第二份内容。
- 用户是否实际使用“继续听”，而不只是试听第一次生成。
- 用户最常导入的来源类型。
- 用户是否愿意使用内置音色长期收听，还是持续选择个人音色。
- 用户放弃任务的环节是导入、等待、听感还是编辑。

如果用户仍然只生成一次，下一步应先修复任务频率和等待体验，而不是继续增加模型或情绪参数。

## 15. 分阶段交付

### v0.4：听读箱基础

- “我的朗读”升级为“我的听读”。
- 记录来源类型和播放进度。
- 支持文字、网页和可提取文字的 PDF。
- 第一段完成即可播放。
- 保持现有个人音色、局部重做和导出能力。

### v0.5：本地音视频转写

- 导入本地音频和视频。
- 字幕优先，无字幕时离线转写。
- 转写和生成支持断点恢复。
- 真实 M1 8GB／16GB 性能验证。

### v0.6：轻量整理与出口

- 浏览器或分享菜单收集。
- Markdown／纯文本笔记导出。
- 视频网站公开字幕导入。
- 经过验证后再决定是否增加本地“重点听”摘要，不把不可靠的小模型摘要混入原文听读。

## 16. 成功定义

本路线成功的标志不是功能数量，而是用户形成下面的习惯：

> 看到一份暂时没时间看的内容，就把它放进“声音导演”，稍后从上次位置继续听。

只有这个行为出现，产品才从文字转语音工具变成了可重复使用的本地听读产品。
