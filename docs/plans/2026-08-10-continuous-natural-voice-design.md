# 连续自然人声核心设计

- 日期：2026-08-10
- 状态：已经用户确认
- 适用产品：“声音导演”离线 macOS 桌面应用

## 1. 决策

下一阶段选择“声音优先”，先改善连续真人感和生成速度，再扩展视频、音频、PDF 和网页导入。不把产品扩展成完整的 NotebookLM 或知识库复制品。

对普通用户的产品定位保持为：

> 选择音色，粘贴文字，生成一段像本人自然讲出来的离线音频。

## 2. 当前问题

当前 `QwenSpeechEngine` 每次合成都启动新的 Python 进程，而 `GenerationQueue` 以单个短段的文字作为独立请求。这会导致：

- 每段重复加载模型和音色参考。
- 模型不知道前后文，短句开头重复起调。
- 相邻段落的速度、气息、重音和音色容易出现细小跳变。
- 运行时间被重复准备成本放大。

因此本阶段不继续增加强情绪标签，而是先修复生成边界和连续性。

## 3. 用户体验边界

主界面仍然只保留：

1. 选择音色。
2. 粘贴或编辑文字。
3. 生成音频。

不向普通用户显示模型名称、量化精度、随机种子、上下文分组或 Worker 状态。发音词典和局部重做仍放在默认折叠的高级区域。

## 4. 常驻语音 Worker

将一次性命令行调用改为常驻子进程，通过标准输入和标准输出交换一行一个 JSON 消息。

Worker 提供以下命令：

- `initialize`：验证运行时并加载模型。
- `prepare_voice`：预处理当前音色的参考录音和参考文字。
- `synthesize`：生成一个连续语义组。
- `cancel`：取消当前请求。
- `shutdown`：有序释放资源。

同一次项目生成期间只加载一次模型，同一音色只准备一次参考特征。已经完成的音频在每个语义组结束后立即原子保存。

安全和恢复策略：

- Worker 意外退出时自动重启一次，只重试未完成的语义组。
- 不在同一成品中静默换模型或换音色。
- 内存不足时停止当前生成并提示兼容路线，不要求升级 macOS。
- 不安装 Homebrew、Docker 或系统组件。

## 5. 连续语义组

项目仍保留用户可编辑的短段，但底层根据以下条件把相邻短段组成连续语义组：

- 优先保持同一自然段和同一话题。
- 以 80～180 个汉字为目标范围，不用固定字数破坏完整句子。
- 标题、明显换行、强转折和总结可以开启新语义组。
- 一个语义组内只调用一次 TTS，减少短句起调和气息重置。

用户修改一个短段后，只让它所属的语义组失效，其他语义组的音频继续复用。

首版不依赖复杂的字级强制对齐。语义组作为最小的合成和重做单位，用户看到的短段仍用于编辑和朗读稿对照。

## 6. 一次引导式音色录入

用户仍只完成一次录入，不需要表演开心、愤怒或悲伤。引导文稿总长约 45～60 秒，覆盖陈述、疑问、转折、数字、日期、英文缩写和长短句。

应用保存原始录音，并根据响度、削波、底噪和静音选择稳定区间。仅在明显底噪时使用清理版，不通过强降噪消除人声高频细节。

## 7. 发音词典

新增可选的项目级和全局级发音规则：

- 原文和展示的朗读稿不变。
- 仅在提交给语音引擎前应用发音替换。
- 规则覆盖人名、地名、品牌、多音字和英文缩写。
- 词典入口放在高级编辑中，不成为首次使用的必填步骤。

## 8. 模型候选与发布边界

研发阶段对比：

1. 当前 Qwen3-TTS 0.6B MLX 基线。
2. Spark-TTS 0.5B MLX。
3. Chatterbox Multilingual MLX。
4. GPT-SoVITS V4 仅作为专业音色研发样本。

发布包不同时携带所有模型。只有在普通话自然度、音色相似度、电子感、生成时间和峰值内存上通过测试的默认模型才进入便携版。

IndexTTS2 只用于研究“音色身份与表达方式分离”的产品思路，因其自定义许可证不进入正式产品。

## 9. 设备策略

- 实际支持结论必须来自真实 M1 8GB 和 16GB 设备长跑。
- 在 32GB 开发机上限制进程资源只用于提前发现问题，不冒充真机结论。
- 生成引擎由设备策略自动选择，普通用户不手动选模型。
- 始终保留不升级 macOS 也可完成的兼容路线。

## 10. 验证标准

### 10.1 功能

- 一次全文生成只加载一次模型。
- 取消、崩溃和重开后不丢失已完成语义组。
- 修改一句只使对应语义组失效。
- WAV、M4A 和 MP3 仍能在没有安装应用的设备上播放。

### 10.2 听感

使用同一音色和同一文稿，对比当前单短段方案与连续语义组方案。评价：

- 段落之间是否存在重新起调。
- 语速、气息、重音和音色是否连续。
- 是否仍有金属感、电流感或水声。
- 连续收听十分钟是否会快速疲劳。

听感没有明显改善时，不因为已经完成技术改造就宣称升级成功。

### 10.3 性能和系统边界

- 记录模型加载次数、首段时间、全文时间和峰值内存。
- 关闭网络后完成整个生成和导出流程。
- 检查应用只写入自己的用户资料和音乐导出目录。
- 不更改系统版本、系统设置或系统组件。

## 11. 实施顺序

1. 定义常驻 Worker 协议并改造 Qwen 运行器。
2. 增加 Worker 生命周期、取消、崩溃恢复和自检。
3. 增加连续语义组数据结构、分组规则和局部失效。
4. 通过常驻 Worker 以语义组为单位生成。
5. 再实现一次引导式录入和发音词典。
6. 最后拉取并评测候选模型，不把研发模型打入正式应用。
