# Open Notebook 口语导演层实施计划

- 依据：`docs/superpowers/specs/2026-08-10-open-notebook-spoken-director-integration-design.md`
- 上游参考：`lfnovo/open-notebook@a7de90d38aaf18ee85fd661854d35c11e44613e2`、`lfnovo/podcast-creator@904da36cca12846e8c610fff5cab2972735b007d`
- 边界：不嵌入上游 Web 服务、数据库或 Docker；不升级 macOS；不安装系统组件；首轮不下载未经低配验证的文字模型。

## 1. 项目格式与兼容迁移

修改：

- `NarrationProject.swift`
- `NarrationSegment.swift`
- `tests/ProjectMigrationSelfTest.swift`

实现：

- 项目格式升级为 v4，增加自然讲解／逐字朗读模式、口语整理版本、提纲和整理状态。
- 段落同时保存不可覆盖的原文与实际朗读稿，增加讲解者角色和口语稿指纹。
- 保留 `text` 兼容访问，旧项目的原文、候选音频、语速与停顿继续可用。
- 旧项目迁移时将原段落文字同时作为原文和朗读稿，不强制重新生成音频。

验证：

- 先补迁移失败测试，再实现解码、编码和无损重存。
- 单独运行 `ProjectMigrationSelfTest`，随后运行全部自检。

## 2. 离线口语导演与保真检查

新增：

- `SpokenScriptDirector.swift`
- `SpokenScriptValidator.swift`
- `tests/SpokenScriptDirectorSelfTest.swift`
- `tests/SpokenScriptValidatorSelfTest.swift`

实现：

- 建立 `SpokenScriptDirecting` 协议以及提纲、口语段落和结果数据结构，给后续小型本地模型留下稳定接口。
- 首轮实现 `RuleSpokenScriptDirector`：保留全部词语和事实，只做空白整理、朗读标点和 20～55 字优先的自然停连分段。
- 逐字朗读模式保留原表达，只进行安全分段。
- 检查数字、百分比、日期、英文缩写、空段、舞台说明、Markdown 标记和过长片段。
- 规则结果必须通过“去除空白与标点后内容完全一致”的强校验；失败自动回退逐字朗读。

验证：

- 固定语料覆盖人名、金额、百分比、版本号、否定句、列表、中英文混排和长句。
- 同一输入两次输出相同段落 ID 与指纹。
- 测试故意改变数字、英文词或加入情绪说明时必须被拒绝。

## 3. 工作区生成流程接入

修改：

- `NarrationWorkspaceModel.swift`
- `NarrationDirector.swift`
- `GenerationQueue.swift`（仅在需要明确朗读稿字段时做最小修改）
- `tests/NarrationDirectorSelfTest.swift`

实现：

- 新建或原文改变时先运行口语导演，再由现有导演分配类别、稳定 ID、语速与停顿。
- 整理成功立即保存；失败保存回退状态并继续逐字朗读，不阻断用户生成音频。
- 修改一段朗读稿只让该段音频失效；恢复原文也只重做该段。
- 切换自然讲解／逐字朗读后重新安排段落，但在新结果通过校验前不破坏原项目。
- 正式长文生成只使用 Qwen 自然人声；资源不足时使用现有兼容路线，不再自动进入 CosyVoice 情绪路线。

验证：

- 模型单元测试覆盖模式切换、单段修改、恢复原文、失败回退和缓存失效范围。
- 生成队列既有断点续传、单段重试和候选保留测试继续通过。

## 4. 简洁界面与高级稿件编辑

修改：

- `ProjectEditorView.swift`
- `SegmentEditorRow.swift`

界面方向：

- 继续使用现有安静的本机工作台配色：墨色 `#20242B`、纸白 `#F9FBFD`、浅蓝纸 `#ECF2FA`、工作蓝 `#2E68C7`、完成绿 `#2F9D62`。
- 保持 macOS 系统字体；标题用现有克制衬线，正文和控制使用系统无衬线，数据使用等宽数字。
- 首屏只增加“自然讲解”一句说明，不增加模型、提示词或保真参数。
- 唯一识别点放在高级编辑：每段展开后以“原文”和“实际朗读”上下对应，差异一眼可见。

实现：

- 高级编辑增加“自然讲解／逐字朗读”模式选择和简短状态。
- 段落卡片默认只展示实际朗读内容；展开后显示只读原文、可编辑朗读稿和“恢复原文”。
- 撤下开心、兴奋、悲伤、愤怒和强度控制，不再让普通用户承担失败的情绪表演选择。
- 新控件全部使用原生 SwiftUI 控件、明确标签、帮助文字和禁用原因；键盘可达，状态不只依赖颜色表达。

验证：

- 编译原生应用并检查新增控件的辅助功能名称。
- 启动应用截图复核：首屏没有新增操作负担，高级区能完成模式切换、编辑和恢复。

## 5. 打包瘦身与来源记录

修改：

- `build.sh`
- `README.md`

新增：

- `ThirdParty/OpenNotebook/NOTICE.md`
- `ThirdParty/OpenNotebook/LICENSE`

实现：

- 便携构建不再调用情绪运行时打包，也不复制 CosyVoice 模型；研发实验目录保留。
- 保留 Qwen、兼容引擎、降噪、导出和 LAME 资源。
- 记录借鉴的上游项目、固定提交、MIT 许可证和本地改写范围。
- README 改为自然讲解流程，删除正式产品已具备情绪表演的描述，并明确规则基线与低配设备边界。

验证：

- 构建产物扫描不得包含 CosyVoice、用户录音、项目 JSON、绝对开发路径或密钥。
- 比较构建体积并确认临时签名验证通过。

## 6. 完整回归与本机试听样本

执行：

- 运行全部 Swift 自检。
- 构建 developer 版本，启动并验证项目创建、模式切换、编辑、恢复、生成、播放和导出。
- 构建 portable 版本，执行签名检查、隐私扫描和包内资源检查。
- 用同一段普通话、同一音色生成“原文直读”和“自然讲解”两个 WAV，保存在独立试听目录并在访达打开。

通过条件：

- 所有自检、编译和签名检查通过。
- 旧项目可以打开并播放既有成品。
- 断网仍能完成口语整理和生成。
- 自然讲解没有丢失或改变测试语料中的事实标记。
- 用户只需试听最终对照结果，不需要了解内部模型或工作流。
