# 单次录音情绪控制设计

## 1. 目标

用户只录制一段普通、自然的普通话声音，就能在朗读项目中选择愤怒、悲伤、开心、兴奋等表达方式。应用使用用户的音色表达情绪，不要求用户表演或分别补录每种情绪。

本功能的三个优先级是：

1. 情绪在听感上能被明确识别，不只是音量或语速的微调。
2. 尽量保持用户音色相似度；强情绪允许有小幅变化，但不能听成另一个人。
3. 优先选择生成更快的可用路线，同时保留完全离线选项。

## 2. 已知边界

当前本地主引擎是 Qwen3-TTS 0.6B Base。Base 模型可以使用参考录音克隆音色，但当前链路不支持在参考音色克隆时同时接收情绪指令。现有 `NarrationExpression` 只影响段落默认速度、停顿和缓存指纹，没有传入语音模型。

因此，本功能不会继续扩展现有的假情绪参数。只有情绪指令确实进入模型并产生可识别差异时，相应选项才能出现在正式界面。

## 3. 方案选择

### 3.1 直接音色克隆加情绪指令（主路线）

一段自然录音只负责表示“这是谁”，情绪指令负责“怎么说”。

- 本地候选：Fun-CosyVoice3 0.5B。官方 `inference_instruct2` 链路可以在零样本参考录音上同时使用表达指令。
- 云端候选：Qwen-Audio 3.0 TTS Flash。官方文档明确标记为同时支持克隆音色和指令控制，克隆音色可接受任意表达指令。

这条路线最符合“只录一次”的产品目标。

### 3.2 公共情绪演员加音色转换（实验路线）

由一个善于表演的人提供情绪模板，再将语音转换成用户音色。这不需要每位用户表演，但需要两次音频生成，容易产生电子感、演员音色泄漏和速度损失。它只用于研发比较，不作为首版产品主路线。

### 3.3 用户多情绪录音（可选增强）

愿意表演的专业用户可以后续补录情绪参考，但这不是创建音色或使用情绪的必要条件。首版不向普通用户展示这个流程。

## 4. 用户体验

### 4.1 音色录入

用户继续只录制或导入一段 10‑20 秒的自然普通话。界面不要求“开心地朗读”或“愤怒地朗读”。现有授权确认、底噪检查、爆音检查和原始录音保留继续有效。

### 4.2 情绪选择

每个段落只保留一个“表达”下拉菜单：

- 自动
- 自然
- 开心
- 兴奋
- 悲伤
- 哀伤
- 愤怒
- 紧张
- 温柔
- 严肃
- 强调重点

选择“自然”以外的固定表达后，再显示“轻微／明显／强烈”三档强度。默认为“明显”。不向用户显示模型名称、温度、音高参数或复杂提示词。

“自动”不通过修改音量伪造情绪，而是向支持的模型发送“根据文字自然判断表达，保持克制”的真实指令。

### 4.3 默认保持简单

主界面仍然是“选择音色、粘贴文字、生成音频”。段落情绪放在默认折叠的高级编辑里。项目主页只显示“已自动安排表达”，不要求用户逐段设置。

## 5. 生成路由

设置页提供三种项目级路由：

1. **自动（推荐）**：在用户已启用云端情绪增强的前提下，根据本机能力、网络状态和表达要求选择已通过验证的引擎。
2. **完全离线**：所有录音和文字都不离开电脑。只显示本机已通过验收的表达。
3. **云端情绪增强**：对强情绪优先使用 Qwen-Audio 3.0 TTS Flash，追求更快首段返回和更明显的表达。

同一个项目的所有段落必须使用同一个引擎和同一个克隆音色资产。不能为了某一段情绪而在成品中混用本地和云端声音，否则会造成明显的音色跳变。

自动路由只能在用户已经开启云端的情况下使用云端，不能隐式上传。

## 6. 组件与数据

### 6.1 ExpressionProfile

新增可序列化的段落表达：

- `emotion`：上述表达枚举。
- `intensity`：`subtle`、`clear`、`strong`。
- `source`：自动或用户手动选择。

输入指纹必须包含表达、强度、引擎版本和云端音色版本。只重新生成发生变化的段落。

旧项目迁移时：

- `natural` → 自然
- `friendly` → 温柔
- `steady` → 严肃
- `emphasized` → 强调重点

### 6.2 EmotionInstructionBuilder

将表达与强度翻译为模型能理解的简体中文指令。每种情绪的指令同时描述语调、节奏、能量和克制程度，但不使用后期变调代替模型表达。

情绪提示词是可版本化的内部资产，不出现在普通用户界面。

### 6.3 LocalExpressiveSpeechEngine

封装 Fun-CosyVoice3 0.5B 或后续通过同样验收的本地模型。必须：

- 使用用户的单段自然参考录音。
- 将表达指令真实传入模型。
- 同一项目期间保持 Worker 与模型常驻，缓存用户音色特征，避免每段重新载入。
- 一次只生成一段，保留暂停、恢复、取消和失败重试。

没有通过真实 M1 8GB 和 16GB 验证前，不标记为正式支持。

### 6.4 CloudExpressiveSpeechEngine

首个候选提供方为 Qwen-Audio 3.0 TTS Flash。云端引擎通过统一协议封装，未来可替换提供方，不让项目格式绑定某一家 API。

克隆音色只需创建一次。本地保存提供方返回的音色标识，不在项目 JSON 里保存 API 密钥。API 密钥使用 macOS Keychain。

### 6.5 ExpressionEngineRouter

在开始生成前一次决定整个项目的引擎，输出可理解的选择原因。项目生成中途不自动换引擎。

## 7. 云端隐私与授权

完全离线仍是可独立完成的产品模式。启用云端前，应用必须一次性说明：

- 会上传用户授权的参考录音用于创建云端克隆音色。
- 会发送当前项目文字用于语音生成。
- 生成结果会下载回本地并继续按 WAV、M4A 和 MP3 保存。

如果云端声音注册接口需要可访问的临时音频 URL，必须使用短时效、不可枚举的签名链接，注册结束后立即删除临时对象并验证不再可访问。没有这个保障时不上线云端克隆。

首版云端实验使用独立的临时对象存储适配器。访问凭证只能保存在 macOS Keychain，签名链接有效期不超过完成一次注册所需的最短时间，临时对象不得被列目录或公开索引。注册成功、失败、取消和超时四种路径都必须触发删除；删除验证失败时，应用明确报警并停止后续云端生成。项目文件不保存录音 URL、对象存储密钥或语音服务密钥。

用户可以在设置中删除云端音色、清除密钥并关闭云端增强。应用不在用户未启用的情况下自动上传。

## 8. 性能策略

- 本地引擎使用常驻 Worker，整个项目只载入一次模型。
- 同一音色的说话人特征只计算一次，不保存没有稳定版本契约的第三方内存对象。
- 云端克隆音色在授权后只注册一次，后续段落只传文字和表达指令。
- 云端段落可在提供方限额内小幅并发，但下载后按段落顺序原子保存。
- 项目级引擎锁定保证同一成品的音色一致性。

## 9. 错误处理

- 情绪不支持：不得静默忽略指令。必须提示“当前完全离线引擎尚不支持这种表达”，并给出使用自然表达或启用云端的单一明确操作。
- 网络中断：已完成段落继续保存，恢复后从第一个未完成段落继续。
- 云端限额或服务异常：暂停项目，不在中途自动换本地引擎。
- 本地内存紧张：当前段回到等待状态。只有自动路由且用户已启用云端时，才可以建议从头使用云端重做整个项目。
- 音色相似度或情绪未达标：不只通过调大后期音量补救，而是重试表达指令或切换经过验收的引擎。

## 10. 验收方法

正式界面开发前，先用同一段用户自然录音和同一批普通话文字完成本地与云端候选测试。

### 10.1 情绪可识别性

每种表达准备至少三段不同文字，隐藏标签后试听。“明显”和“强烈”档不能仅凭音量猜测；应能从语调、节奏和能量听出预期情绪。

发布门槛：每种情绪至少进行五次独立随机盲听；每次从目标情绪和至少两个易混淆情绪中选择，试听者看不到标签和模型名称。至少四次选中目标情绪才算通过。开发阶段由产品负责人完成首轮判断；公开测试阶段再加入不同试听者复核。没有达到的情绪不进入正式下拉菜单。

### 10.2 音色相似度

同时使用固定版本的说话人验证模型与用户盲听。基准开始前锁定验证模型、音频预处理方式和版本，并把它们记录在测试报告中；同一轮候选比较不得更换。以同一引擎的自然表达为基线：

- “轻微”和“明显”的相似度分数不得相对下降超过 10%。
- “强烈”不得相对下降超过 20%，且用户不能听成另一个人。

这些阈值是候选筛选标准，不代替用户最终试听。

### 10.3 音频质量

- 无可感知电流音、金属声、孤立爆音、明显吞字或引擎切换。
- 音量标准化不得抹平愤怒、兴奋和悲伤的动态差异。
- 成品必须继续通过 WAV、M4A 和 MP3 完整性检查。

### 10.4 速度与资源

- 云端 Flash 路线记录首段延迟、整段完成时间、失败率和重试开销。
- 本地路线记录冷启动、热启动、峰值内存和实时率。
- 32GB 开发机结果不能替代真实 M1 8GB 和 16GB 结论。
- 本地引擎没有通过对应真机长文测试前，不在产品页面宣传支持该档位。

## 11. 实施顺序

1. 在隔离实验目录中构建固定测试集，不改正式界面。
2. 用用户的一段自然录音分别评估 Fun-CosyVoice3 0.5B 和 Qwen-Audio 3.0 TTS Flash。
3. 先淘汰情绪不可识别、音色下降过大、电子感明显或速度不合格的路线。
4. 只有候选样本通过用户试听后，才实现 `ExpressionProfile`、引擎路由和真实的情绪下拉菜单。
5. 本地情绪引擎和云端引擎分别通过功能开关发布，不影响现有完全离线项目。

## 12. 非目标

- 不要求普通用户补录多种情绪。
- 不通过简单升降调、变速和增大音量宣称已实现情绪。
- 不在正式界面显示尚未通过盲听的情绪。
- 不让用户在每个段落选择模型或云服务商。
- 不在用户未授权的情况下上传录音、文字或生成结果。
