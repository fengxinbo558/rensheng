# 统一音频播放器与成品失效设计

- 日期：2026-08-09
- 范围：朗读项目、快速生成、音色试听
- 约束：完全本地处理，不安装或修改 macOS 系统组件

## 1. 问题与目标

当前界面只有“播放”动作，没有暂停、继续、停止和进度信息。“暂停生成”与音频播放无关，但名称容易让用户误以为它也能控制播放。项目内容或朗读设置变化后，旧成品仍显示为就绪，也会让用户误听过期结果。

本次目标是建立一个全应用共用的播放器，让用户在生成前后都能明确控制正在播放的音频，并确保界面不会把旧成品标记为最新成品。

## 2. 采用方案

新增单一的 `PlaybackController`，集中持有 `AVAudioPlayer`、播放来源、播放状态、当前时间和总时长。朗读段落、朗读成品、快速生成结果、音色参考录音都交给它播放，任一新音频开始时自动停止上一条。

播放器状态：

- 未载入：没有可控制的音频。
- 播放中：显示“暂停”和“停止”。
- 已暂停：显示“继续”和“停止”，保留当前位置。
- 已结束或已停止：回到起点，显示“播放”。
- 失败：停止并显示中文错误，不保留假播放状态。

## 3. 界面行为

### 朗读项目

- “成品播放器”固定显示播放／暂停、停止、可拖动进度条、当前时间和总时长。
- 每个已完成段落仍有快捷播放按钮；点下后，下方播放器立即切换为“第 N 段”。
- 全文仍在生成时，已经完成的段落可以立即播放；正在生成或尚未生成的段落保持禁用。
- “暂停生成”保留该完整名称，播放器使用“暂停播放”，两者不混用。

### 快速生成与音色试听

- 快速生成结果和音色参考录音复用相同的播放／暂停／停止行为。
- 切换到另一段音频时停止上一条，避免两个声音重叠。

### 成品失效

- 修改原文、音色、表达方式、速度或段后停顿后，项目立刻清空导出记录，界面显示“内容已变化，需要重新生成／制作成品”。
- 旧文件不自动删除；再次制作成品时原子覆盖同名文件，避免不可恢复的数据删除。
- 只要仍有未完成段落，旧成品不再显示“已就绪”，也不能通过播放器误播放。

## 4. 组件边界

- `PlaybackController`：加载、播放、暂停、继续、停止、拖动、时间更新和播放完成回调。
- `PlaybackControlsView`：纯界面组件，只读取播放器状态并发送控制动作。
- `NarrationWorkspaceModel`：决定要播放哪个项目文件，不再直接管理 `AVAudioPlayer`。
- `ProbeViewModel`：负责生成与文件位置，不再创建自己的播放器。
- `ProjectPlayerBar`：显示当前来源、进度和控制按钮，并提供访达入口。

## 5. 数据与错误处理

- 拖动进度限制在 `0...duration`；空文件、损坏文件和路径失效时拒绝播放。
- 播放计时器只在播放时运行，暂停、停止、完成和对象释放时立即取消。
- 项目切换、删除或重新分析时停止当前项目音频，防止继续播放已离开的内容。
- 导出失效只更新项目 JSON 引用，不删除段落母版和旧成品文件。

## 6. 辅助功能

- 控件使用明确中文标签：“播放”“暂停播放”“继续播放”“停止播放”“播放进度”。
- 进度条提供“已播放 X，音频共 Y”的辅助功能值。
- 播放来源通过文字和辅助功能状态同时呈现，不只依赖图标或颜色。

## 7. 验收标准

1. 成品播放后按钮变为“暂停播放”，暂停后变为“继续播放”，停止后回到起点。
2. 拖动进度条后从新位置继续播放，时间显示同步更新。
3. 生成过程中可以播放任一已完成段落，且不影响后台继续生成。
4. 新播放会停止旧播放，不出现两条音频重叠。
5. 修改任一会影响音频的设置后，旧成品不再显示为最新成品。
6. 朗读项目、快速生成、参考音色三处控制语义一致。
7. 现有项目存储、生成恢复、三格式导出和便携构建测试继续通过。
