# 私人声音出版台设计

日期：2026-08-11

## 目标

把“声音导演”从一个本地文字转语音工具，收拢为面向知识创作者、老师和课程制作者的私人声音出版台。

核心承诺是：用户录入一次自己的声音，就能把自己的文稿长期制作成可修改、可续作、可交付的声音作品。用户修改一段，只需重做这一段；原稿、声音、分段母版和成品默认保留在本机。

这一轮不把“音质超过豆包”作为成功标准。语音模型是可替换的底层引擎，产品价值来自项目、编辑、复用和交付工作流。

## 首批用户与核心任务

首批用户是需要反复把文稿、课程或知识内容制作成音频的创作者和老师。

他们的核心任务不是偶尔听一篇文章，而是：

1. 导入一份会继续修改的内容。
2. 用稳定的个人或授权音色制作音频。
3. 发现读法或文字问题后，只修改局部。
4. 快速试听修改结果。
5. 导出可以直接交付、上传或发送的通用音频文件。

## 现状复用

项目已经具备以下能力，本轮直接复用，不重新实现：

- 本地项目与原文保存；
- 文本、可搜索 PDF 和网页导入；
- 自然讲解与逐字朗读；
- 逐段生成、取消、重试与断点继续；
- 单段文字修改、速度、停顿和单段重做；
- 同一段多个声音版本；
- WAV、M4A、MP3 成品；
- 播放位置保存；
- 本地音色库与个人音色录入。

因此，本轮重点是重新组织这些能力，让用户一眼看懂“这是作品工作台”，并补齐直接交付的最后一步。

## 产品结构

### 1. 全局入口

保留两个入口：

- “声音作品”：默认入口，面向可保存、可修改、可交付的长期项目；
- “快速生成”：面向 500 字以内的一次性试听。

旧名称“朗读项目”“我的听读”统一改为“声音作品”“作品库”。内部数据结构名称暂不改，避免无价值的数据迁移。

### 2. 作品页的状态切换

新建作品时，来源编辑区默认展开，用户能直接粘贴、导入 PDF 或网页。

项目已经产生分段后，来源编辑区默认折叠成摘要卡，展示来源、字数、音色和更新时间。页面首屏改为作品进度、播放和交付，不再让长文本框占据主要空间。

用户随时可以展开“查看或修改原稿”。修改后，应用沿用现有指纹机制，只令受影响的片段失效。

### 3. 出版进度条

在作品页加入四阶段出版轨道：

1. 原稿：来源已保存；
2. 朗读稿：已经整理为语义段；
3. 声音：显示已完成片段数；
4. 成品：显示 WAV、M4A、MP3 是否齐备。

它不是要求用户逐步点击的向导，而是只读状态摘要。这样既能解释系统正在做什么，又不增加操作负担。

### 4. 作品编辑

把“高级编辑”改名为“编辑作品”，副标题固定说明“修改一段，只重做这一段”。

默认仍折叠，避免初次使用复杂；用户展开后继续使用现有逐段编辑器：

- 对照原文；
- 修改实际朗读稿；
- 恢复原文；
- 调整成品速度和段后停顿；
- 选择已有声音版本；
- 单独播放或重新生成当前段。

本轮不重新开放情绪滑杆。当前个人音色路线不能稳定兑现这些控制，展示无效控制会损害信任。

### 5. 成品交付

成品卡保留播放、暂停、停止、进度和试听速度，并新增“导出成品”菜单：

- 导出 M4A（推荐，体积较小）；
- 导出 MP3（兼容性最好）；
- 导出 WAV（无损母版）。

选择格式后打开 macOS 原生保存面板，默认使用项目名称作为文件名。导出只是复制已经生成并验证过的本地成品，不重新合成。

原有“在访达中显示”继续保留。

## 视觉方向

主题是“安静的声音工作室”，不是网页仪表盘。

- 墨蓝 `#17223B`：主文字和作品标题；
- 信号蓝 `#3B6FE8`：主要动作和当前阶段；
- 波形薄荷 `#DFF3EF`：可播放成品区域；
- 纸面白 `#F7F9FC`：主背景；
- 轨道灰 `#E9EEF6`：分隔与未完成阶段；
- 提醒琥珀 `#C27A2C`：需要处理的状态。

标题使用 macOS 系统衬线体，功能标签使用圆体，正文使用系统默认字体。唯一有辨识度的视觉元素是四阶段“出版轨道”；其他卡片保持克制，避免每个区域都争抢注意力。

## 无障碍与桌面行为

- 所有按钮、菜单、输入框和展开项使用原生 SwiftUI 控件；
- 图标按钮必须有可朗读名称；
- 状态不能只靠颜色区分，同时显示文字或符号；
- 展开区可通过键盘操作；
- 导出失败既更新页面状态，也显示明确原因；
- 不自动播放声音；
- 不添加无意义动画。

## 错误与数据安全

- 不修改项目存储格式，旧项目直接打开；
- 不删除旧成品、分段母版或声音资料；
- 用户删除项目仍使用系统废纸篓；
- 导出目标由系统保存面板确认；
- 成品缺失时禁用对应格式，不创建空文件；
- 导出失败不影响项目内原始成品；
- 不安装依赖、不修改系统设置、不要求升级 macOS。

## 失败预演

### 失败一：用户仍把它当成普通 TTS

触发条件：完成项目后首屏仍被原稿输入框占据。用户看不到局部修改和交付能力，于是直接与豆包比较单次音质。

缓解：有分段的作品默认折叠原稿，把出版轨道、播放、编辑和导出提前到首屏。

### 失败二：增加很多按钮，反而更难用

触发条件：把内部每个参数都暴露给用户，作品页出现十几个需要理解的选择。

缓解：主流程仍只有导入、选择音色、生成。出版轨道只读，逐段设置默认折叠。

### 失败三：为了新卖点再次牺牲稳定性

触发条件：本轮同时替换语音模型、增加双人脚本和重构项目数据，任何一个不稳定都会阻断成品交付。

缓解：本轮不换模型、不改存储格式，只重组已验证能力并补齐导出。

### 失败四：用户完成了作品却找不到文件

触发条件：成品只留在应用内部目录，用户必须理解访达路径和多种文件格式。

缓解：提供明确的“导出成品”，使用系统保存面板和项目默认文件名。

## 验收标准

1. 新作品默认展示来源输入；已有分段的作品默认展示作品结果。
2. 首屏能看见四阶段出版状态、播放区域和“编辑作品”。
3. 用户能展开原稿并继续修改。
4. 用户能选择 M4A、MP3 或 WAV 导出到指定位置。
5. 导出文件可以被系统播放器打开，且大小大于零。
6. 旧项目无需迁移即可使用。
7. 所有现有自动化自检通过。
8. 便携应用仍为临时签名，不改变最低 macOS 版本，不修改系统组件。

## 本轮明确不做

- 账号、订阅和支付；
- 在线发布平台；
- 完整多轨音频编辑器；
- 视频剪辑；
- 双人播客联合生成；
- 新情绪模型接入；
- 云端 TTS 接入；
- 项目存储格式迁移。
